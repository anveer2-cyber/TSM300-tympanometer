# 청력검사 원자료 형식 (`exam: "hearing"`, `format: 1`)

TSM300 이 청력검사기(MRS Resonance)에서 받은 순음 · 어음 · 음장 검사를 저장하는 형식입니다.
나중에 이 원자료를 상쾌한캡처 서버로 보내 장애진단서 · 산재 서류를 자동으로 채울 때, 받는 쪽이 따를 약속입니다.

- 만든 날: 2026-11-27 (TSM300 v0.11.0)
- 더한 칸: 2026-11-27 손으로 고친 값(`corrections`, 값마다 `corrected` · `device_value`), 직접 입력(`source`), 특이사항(`remarks`), 이명도검사(`tinnitus`). 더하기만 했으므로 `format` 은 그대로 1 (11~13절)
- 만드는 코드: `src/tsm300/hearing/record.py` 의 `record()`, 공통 칸은 `src/tsm300/store.py` 의 `result_to_dict()`
- 시험: `tests/hearing/test_hearing_record.py` · `test_hearing_edits.py` 가 칸 이름과 값을 확인합니다. 칸을 바꾸면 이 시험이 먼저 깨집니다.

## 1. 파일

한 결과지마다 같은 이름의 파일 세 개가 저장 폴더에 생깁니다. 임피던스(중이검사) 결과와 같은 폴더, 같은 이름 규칙입니다.

| 파일 | 내용 |
| --- | --- |
| `20261127_103005_00512.json` | 이 문서의 형식. 해독한 값 전부와 패킷 원본(16진수) |
| `20261127_103005_00512.bin` | 기기가 보낸 패킷 그대로. 기기 환자(`KA`) 다음에 그 환자의 검사(`KT`)가 받은 순서대로 이어 붙음. 값을 손으로 고쳐도 바뀌지 않음. 직접 입력한 결과는 빈 파일(0 바이트) |
| `20261127_103005_00512.jpg` | A4 결과지 (300 dpi, 2480×3508) |

이름은 `받은날_받은시각_차트번호`. 환자 정보 없이 저장하면 차트번호가 빠집니다. 같은 이름이 있으면 `_2`, `_3` 이 붙습니다.
[출력]이나 [컴퓨터에 보관]을 누르면 `보관\2026-11\2026-11-27\00512_홍길동_1030.*` 에 사본이 생깁니다. 사본의 JSON 에는 `filed_from`(원본 결과지 경로)이 더 있습니다.

## 2. 버전 규칙

- 읽는 쪽은 `exam == "hearing"` 이고 `format == 1` 인 것만 이 문서대로 읽습니다.
- 칸은 **더해질 수 있습니다.** 모르는 칸은 무시해 주세요. 이때 `format` 은 그대로입니다.
- 칸을 빼거나 뜻을 바꾸면 `format` 을 2 로 올립니다.
- `exam` 이 없거나 `"tymp"` 이면 임피던스 결과입니다(형식이 다름).
- 값이 없으면 `null`, 검사하지 않은 주파수는 `points` 에 아예 없습니다.

## 3. 맨 위 칸

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| `format` | 정수 | 1 |
| `exam` | 글자 | `"hearing"` (상쾌한캡처가 순음청력검사에 쓰는 이름) |
| `received_at` | `YYYY-MM-DDTHH:MM:SS` | 기기에서 받은 시각. 파일 이름의 시각. 바뀌지 않음 |
| `tested_at` | 같은 형식 | 결과지에 인쇄한 검사일시. 처음에는 받은 시각(분 단위)이고, 직원이 고칠 수 있음. **기기는 검사 날짜를 보내지 않습니다** |
| `clinic` | `{name, address, phone}` | 결과지에 인쇄한 병원 |
| `patient` | `{chart_no, name, sex, birth_date}` | 직원이 프로그램에서 고른 환자. `sex` 는 `"남"`/`"여"`/`""`, `birth_date` 는 `YYYY-MM-DD` 또는 `null`. 환자 없이 저장했으면 모두 빈 값 |
| `note` | 글자 | 결과지 메모 (인쇄됨) |
| `remarks` | 글자 | 특이사항. 직원이 남긴 말로, **결과지에 인쇄하지 않고** 상쾌한캡처로도 보내지 않음. 없으면 `""` |
| `source` | 글자 | `"device"` 청력검사기에서 받음 · `"manual"` 기기 없이 손으로 입력 (12절) |
| `device` | 아래 또는 `null` | 청력검사기. 직접 입력이면 `null` |
| `device_patients` | 목록 | 기기에 입력되어 있던 환자 (아래) |
| `tests` | 목록 | 이 결과지에 들어간 기기 검사 하나하나 (아래) |
| `tone` | 객체 또는 `null` | 순음 · 음장 (아래) |
| `speech` | 객체 또는 `null` | 어음 (아래) |
| `high_frequency` | 객체 또는 `null` | 고주파 순음 8~20 kHz (아래) |
| `tinnitus` | 객체 또는 `null` | 이명도검사, 손으로 넣은 값 (13절). 하나도 넣지 않았으면 `null` |
| `corrections` | 목록 | 손으로 고친 값 하나하나 (11절). 고친 것이 없으면 `[]` |
| `capture` | 목록 | 상쾌한캡처로 결과지를 보낸 기록, 오래된 것부터 (임피던스와 같음) |
| `filed` | 글자 | 보관 사본의 경로(확장자 없이). 없으면 `""` |

### `device`

```json
{"maker": "MRS", "name": "Resonance", "model": "R37A", "serial": "R37A21C000777", "serials": ["R37A21C000777"]}
```

`model` 은 일련번호 앞 네 글자. 검사들이 여러 기기에서 왔으면 `serials` 에 모두 있고 `serial` 은 첫 번째입니다.

### `device_patients[]`

기기 화면에서 입력한 그대로입니다. 우리 환자(`patient`)와 다를 수 있습니다. 대조용으로만 쓰세요.

| 칸 | 뜻 |
| --- | --- |
| `number` | 기기 안의 환자 번호 |
| `pc_number` | PC 프로그램이 기기에 올릴 때 준 번호 (기기에서 입력하면 `"0"`) |
| `first_name`, `surname`, `name` | 이름 · 성 · 둘을 이은 것(성 이름 순) |
| `birth_date` | 기기에 적힌 그대로, `dd/MM/yyyy` |
| `birth_date_iso` | 그것을 `YYYY-MM-DD` 로 읽은 것. 못 읽거나 1800년(제조사의 "모름")이면 `null` |
| `sex` | 기기 값 그대로 (`"M"`, `"F"` 등) |
| `packet` | `KA` 패킷 원본, 16진수 |

### `tests[]`

| 칸 | 뜻 |
| --- | --- |
| `index` | 0부터. 아래 곡선의 `test` 가 이 번호를 가리킴 |
| `type` | `"tone"` 순음(음장 포함) · `"speech"` 어음 · `"high_frequency"` 고주파 순음 |
| `name` | 기기 검사 이름 (`"순음청력"`, `"어음청력"`, `"고주파 순음"`) |
| `mode`, `test` | 패킷의 모드 · 검사 번호 (순음 0/0, 어음 0/1, 고주파 0/11) |
| `serial`, `model` | 그 검사를 한 기기 |
| `aided` | **직원이 "보청기 착용"으로 표시한 검사.** 이 검사의 음장 곡선은 `SpkrA`(보청기 착용 음장)로 들어감 |
| `device_patient` | `device_patients` 의 번호, 또는 `null` |
| `fingerprint` | 패킷 원본의 SHA-1. 같은 검사를 두 번 받으면 같음 |
| `length` | 패킷 바이트 수 |
| `packet` | `KT` 패킷 원본, 16진수. 해독은 `src/tsm300/hearing/protocol.py`, 요약은 `통신_절차.md` |

## 4. 곡선의 종류 (`kind`)와 귀 (`ear`)

`ear` 는 `"R"`(오른쪽) 또는 `"L"`(왼쪽).

| `kind` | 뜻 | 결과지 줄 |
| --- | --- | --- |
| `Ac` | 기도 | 기도 |
| `Bc` | 골도 | 골도 |
| `Spkr` | 음장, 보청기 없이 | 음장 |
| `SpkrA` | 음장, 보청기 끼고 | 음장 보청기 |
| `AcU` | 불쾌역치(UCL) | 불쾌역치 |
| `AcM` | 쾌적역치(MCL) | 쾌적역치 |
| `Ac1`, `Bc1`, `Spkr1`, `SpkrA1` | 어음 둘째 단어 목록 (어음에만) | 결과지에 없음 |

곡선마다 `kind` 와 `device_kind` 가 있습니다. `kind` 는 결과지에 넣은 자리, `device_kind` 는 기기가 붙인 이름입니다.
둘이 다른 것은 `aided` 검사뿐입니다: 기기는 `Spkr` 로 보냈지만 직원이 보청기 착용으로 표시해서 `SpkrA` 로 들어간 곡선입니다.
기기가 보내지 않은 곡선을 직원이 손으로 채웠으면 `device_kind` · `test` 와 기기 설정 칸(`stimulus`, `masking_signal`, `pulsed`, `material`)이 `null` 입니다.
한 결과지에서 (`kind`, `ear`) 하나에는 곡선이 하나뿐입니다. 두 검사에 같은 곡선이 있으면 프로그램이 저장하지 않습니다.

## 5. `tone` — 순음 · 음장

```json
{"curves": [ ... ], "averages": [ ... ]}
```

`curves[]` (오른쪽 먼저, 그 안에서 위 표 순서):

| 칸 | 뜻 |
| --- | --- |
| `ear`, `kind`, `device_kind` | 위 4절 |
| `test` | `tests[]` 번호 |
| `stimulus` | 자극음 (`TONE`, `WARBLE`, `NBNOISE` …) |
| `masking_signal` | 차폐음 종류 |
| `pulsed` | 단속음이면 `true` |
| `points[]` | 검사한 주파수만, 낮은 것부터 |

`points[]`:

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| `frequency_hz` | 정수 | 125, 250, 500, 750, 1000, 1500, 2000, 3000, 4000, 6000, 8000, 10000, 12500 |
| `level_db_hl` | 정수 | 역치 dB HL. 무반응이면 준 가장 큰 소리 |
| `masking_db` | 정수 또는 `null` | 차폐 크기 dB. 차폐하지 않았거나 크기를 모르면 `null` |
| `masked` | 참/거짓 | 차폐했는지. 무반응+차폐는 `masked: true`, `masking_db: null` |
| `no_response` | 참/거짓 | 무반응 (결과지에 `↓`) |

`averages[]` — `Ac`, `Bc`, `Spkr`, `SpkrA` 곡선마다 세 가지 평균:

| 칸 | 뜻 |
| --- | --- |
| `ear`, `kind` | 어느 곡선의 평균인지 |
| `method` | `"3분법"` (500+1k+2k)/3 · `"4분법"` (500+2×1k+2k)/4 · `"6분법"` (500+2×1k+2×2k+4k)/6 |
| `weights` | 주파수별 가중치, 예: `{"500": 1, "1000": 2, "2000": 2, "4000": 1}` |
| `value` | 계산한 값 (소수 넷째 자리까지) 또는 `null` (해당 주파수를 하나도 안 함) |
| `shown` | 결과지에 인쇄한 정수: **소수점 아래 버림** (56.7 → 56, −2.5 → −2). 제조사 한국어 결과지와 같음 |
| `text` | 결과지에 인쇄한 글자 그대로. `shown` 뒤에 `↑`(무반응 주파수가 들어감) · `*`(빠진 주파수가 있음) |
| `at_least` | 무반응 주파수를 그 값(준 가장 큰 소리)으로 넣어 셈. 실제 청력은 이보다 나쁘거나 같음 |
| `missing_hz` | 검사하지 않아 빼고 평균한 주파수. 비어 있으면 다 들어감 |

계산법은 제조사 한국어 결과지와 같습니다: 무반응도 그 값으로 넣고, 검사하지 않은 주파수는 빼고 남은 가중치로 나눕니다.
장애 판정에 쓸 때는 `at_least` 와 `missing_hz` 를 꼭 보세요.

## 6. `speech` — 어음

```json
{"curves": [ ... ], "srt": [ ... ]}
```

`curves[]`:

| 칸 | 뜻 |
| --- | --- |
| `ear`, `kind`, `device_kind`, `test` | 위와 같음 |
| `stimulus`, `masking_signal` | 자극 · 차폐 신호 (`SD CARD`, `MIKE` …) |
| `material` | 기기의 단어 목록 번호 |
| `points[]` | 측정한 점, 측정 순서대로 (최대 10개) |
| `best` | 정답률이 가장 높은 점 (같으면 더 작은 소리). 결과지의 "최고 명료도"와 "그때 강도". 없으면 `null` |
| `srt_db_hl` | 같은 (`kind`, `ear`) 의 SRT, 없으면 `null` |

`points[]` 와 `best`:

| 칸 | 뜻 |
| --- | --- |
| `level_db_hl` | 강도 (기기가 보낸 값 그대로, 아래 7절 주의) |
| `score_percent` | 정답률 % 또는 `null` |
| `masking_db`, `masked` | 차폐 |
| `correct` | 맞힌 단어 수. 기기가 보낼 때만 (가장 긴 패킷), 아니면 `null` |
| `words` | 준 단어 수 = 맞힌 수 ÷ 정답률. `correct` 가 없거나 정답률이 0 이면 `null` |

`srt[]` — 기기가 따로 보내는 SRT 값 그대로 (곡선에서 계산하지 않음): `{ear, kind, device_kind, test, level_db_hl}`.

## 7. `high_frequency` — 고주파 순음

`{"curves": [ ... ]}`. 곡선 형식은 `tone.curves` 와 같고 `frequency_hz` 가 8000, 9000, 10000, 11200, 12500, 14000, 16000, 18000, 20000 입니다. `kind` 는 `Ac` 또는 `Spkr`. 평균은 없습니다.

## 8. 실제 기기로 아직 확인하지 않은 것

해독 규칙은 제조사 프로그램과 102개 항목을 대조해 같았지만, 실제 기기의 패킷으로는 아직 보지 못했습니다. 첫 병원 연결 때 바이트 기록(`청력검사기_기록\*.txt`)으로 확인할 것입니다 (`통신_절차.md` §8).

- 음수 역치(−10, −5 dB)가 이대로 읽히는지
- 무반응 점의 `level_db_hl` 이 기기 최대 출력인지, 마지막으로 준 소리인지
- 어음 `level_db_hl` 이 기기 화면의 dB HL 과 같은지 (제조사 프로그램 곳곳에 +20 이 섞여 있음)
- `Spkr` 의 `R`/`L` 이 "스피커 방향"인지 "평가한 귀"인지
- `correct` · `words` 가 이 병원 기기에서 오는지

확인 뒤 뜻이 바뀌면 `format` 을 올리고 여기에 적습니다.

## 10. 원본에서 다시 읽기

`.json` 의 값이 의심스러우면 `.bin`(또는 `tests[].packet`)을 다시 해독하면 됩니다. 단, `.bin` 에는 기기가 보낸 값만 있고 손으로 고친 값은 없습니다.
TSM300 은 결과를 다시 열 때 `.bin` 을 해독하고, `.json` 에서는 `tests[].aided`(직원의 보청기 착용 표시, `fingerprint` 로 맞춤)와 `corrections`(손으로 고친 값)만 가져와 그 위에 다시 얹습니다.

## 11. 손으로 고친 값

직원은 [검사 값 고치기...]에서 역치 · 차폐 · 무반응, 어음 점, SRT 를 고치거나, 기기가 보내지 않은 줄(예: 불쾌역치)을 채우거나, 값을 지울 수 있습니다.
**결과지에는 고친 값이 표시 없이 그대로 인쇄됩니다.** 기기가 보낸 값은 `.bin` 에 그대로 있고, JSON 에서만 둘을 구별합니다.

읽는 쪽이 할 일: 아래 값 칸(`tone`, `speech`, `high_frequency`)은 **결과지에 인쇄된 값**이니 그대로 쓰면 됩니다. 손으로 고친 값인지 알고 싶으면 `corrected` 를 보세요. 칸이 없으면 `false` 입니다.

### 값 칸의 표시

| 어디에 | 칸 | 뜻 |
| --- | --- | --- |
| `tone.curves[].points[]`, `high_frequency.curves[].points[]`, `speech.curves[].points[]` | `corrected: true`, `device_value` | 이 점은 손으로 넣은 값. `device_value` 는 기기가 보낸 그 점(같은 칸 이름, 주파수 · 점 번호는 빼고), 기기가 보내지 않은 점이면 `null` |
| `…curves[]` | `corrected: true` | 이 곡선에 손으로 고친 점이 있음 (지운 점 포함) |
| `…curves[]` | `removed_points` | 기기가 보냈지만 직원이 지운 점. 순음은 `frequency_hz` 포함, 어음은 `point`(측정 순서 번호, 1부터) 포함. 지운 것이 없으면 칸이 없음 |
| `tone.averages[]` | `corrected: true`, `device_value` | 고친 곡선의 평균. `value` · `shown` · `text` 는 고친 값으로 다시 계산한 것(결과지와 같음), `device_value` 는 기기 값으로 낸 평균 `{method, weights, value, shown, text, at_least, missing_hz}` 또는 `null` |
| `speech.srt[]` | `corrected: true`, `device_value` | 손으로 넣은 SRT, 기기 값(정수 또는 `null`) |

어음 점을 손으로 넣으면 `words`(단어 수)는 직원이 넣은 값입니다(기기 값처럼 맞힌 수 ÷ 정답률로 셈하지 않음).
곡선의 점을 모두 지우면 그 곡선은 `curves` 에서 빠지고 `corrections` 에만 남습니다.

### `corrections[]`

값 하나(순음은 주파수 하나, 어음은 점 하나, SRT 하나)마다 한 줄, 결과지 순서(순음 → 고주파 → 어음 → SRT, 오른쪽 먼저)입니다. 기기 값과 같게 되돌린 값은 빠집니다.

| 칸 | 뜻 |
| --- | --- |
| `at` | 손으로 넣은 때 `YYYY-MM-DDTHH:MM:SS`. 다시 고치면 바뀌고, 그대로 둔 값은 처음 때 그대로 |
| `section` | `"tone"` 순음 · 음장 · `"high_frequency"` 고주파 · `"speech"` 어음 점 · `"srt"` 어음 SRT |
| `ear`, `kind` | 4절. `kind` 는 결과지의 줄(보청기 착용이면 `SpkrA`) |
| `frequency_hz` | `tone` · `high_frequency` 만 |
| `point` | `speech` 만. 측정 순서 번호, 1부터 (기기가 보낸 점의 순서, 손으로 넣은 점은 그 번호 자리) |
| `device_value` | 기기가 보낸 값. 순음은 `{level_db_hl, masking_db, masked, no_response}`, 어음은 `{level_db_hl, score_percent, masking_db, masked, correct, words}`, SRT 는 정수. 기기가 보내지 않았으면 `null` |
| `value` | 결과지에 인쇄한 값, 형식은 같음. 지운 값이면 `null` |

```json
{"at": "2026-11-27T10:41:00", "section": "tone", "ear": "R", "kind": "Ac", "frequency_hz": 1000,
 "device_value": {"level_db_hl": 55, "masking_db": null, "masked": false, "no_response": false},
 "value": {"level_db_hl": 60, "masking_db": null, "masked": false, "no_response": false}}
```

무반응 + 차폐는 기기에서는 차폐 크기 없이(`masking_db: null`) 오지만, 손으로는 차폐 크기와 함께 넣을 수 있습니다(`masked: true`, `masking_db: 80`, `no_response: true`).

## 12. 직접 입력 (`source: "manual"`)

청력검사기 없이 [직접 입력...]으로 값을 모두 손으로 넣은 결과입니다. 다른 결과와 같은 이름 규칙으로 세 파일이 생기고, 같은 방법으로 출력 · 보관 · 상쾌한캡처(`hearing`)로 보냅니다.

- `device: null`, `device_patients: []`, `tests: []`, `.bin` 은 빈 파일입니다.
- 모든 값이 `corrections` 에 `device_value: null` 로 들어 있고, 값 칸의 모든 점에 `corrected: true`, `device_value: null` 이 붙습니다. TSM300 은 다시 열 때 `corrections` 로 값을 만듭니다.
- 결과지 맨 아래에는 장비 일련번호 자리에 아무것도 쓰지 않고 `TSM300 v…` 만 나옵니다.

## 13. `tinnitus` — 이명도검사 (손으로 넣음)

기기의 이명 검사(모드 0, 검사 35)는 해독하지 않습니다(제조사 프로그램도 하지 않고, 그 한국어 결과지의 TINNITUS GRAM 표도 손으로 넣습니다).
그래서 이명도검사 값은 늘 직원이 [검사 값 고치기...] 나 [직접 입력...]의 "이명" 탭에 넣은 것입니다. 기기 값이 없으니 `corrections` 에는 들어가지 않습니다.
이명만 넣은 결과(직접 입력)도 됩니다. 그때 `tone` · `speech` 는 `null` 입니다.

값을 하나라도 넣었으면 두 귀 모두 일곱 칸이 다 있습니다.

```json
"tinnitus": {
  "R": {
    "pitch_hz":              {"text": "4000", "value": 4000},
    "loudness_db":           {"text": "10 dB SL", "value": 10},
    "threshold_db":          {"text": "85 dB (o)", "value": 85},
    "masking_noise_db":      {"text": "Mo51dB", "value": 51},
    "minimum_masking_db_hl": {"text": "40", "value": 40},
    "residual_inhibition_s": {"text": "30", "value": 30},
    "inhibition":            {"text": "완전 억제", "value": null},
    "plotted": {"frequency_hz": 4000, "level_db_hl": 85, "from": "SL"}
  },
  "L": {"pitch_hz": {"text": "", "value": null}, "…": "…", "plotted": null}
}
```

| 칸 | 결과지 | 제조사 결과지 |
| --- | --- | --- |
| `pitch_hz` | 이명 주파수 (Hz) | Pitch Matching [Hz] |
| `loudness_db` | 이명 크기 (dB) | Loudness Matching |
| `threshold_db` | 청력역치 (dB) | Hearing Threshold |
| `masking_noise_db` | 차폐 잡음 역치 (dB) | Masking Noise Threshold |
| `minimum_masking_db_hl` | 최소 차폐 크기 (dB HL) | Minimum Masking Level [HL] |
| `residual_inhibition_s` | 잔류 억제 (초) | Residual Inhibition [sec] |
| `inhibition` | 억제 특성 (완전 억제 · 부분 억제 · 억제 없음 · 반동 또는 아무 글) | Inhibition Characteristic |

- `text`: 직원이 넣은 그대로(앞뒤 공백과 겹친 공백만 줄임, 40자까지). 넣지 않았으면 `""`. 결과지의 이명 표에는 이것이 인쇄됩니다.
- `value`: `text` 에서 읽은 첫 숫자. `1500`→1500, `28 dB`→28, `85 dB (o)`→85, `Mo51dB`→51, `1.5 kHz`·`1.5k`→1500, `-5 dB`→−5, 숫자가 없으면(`완전 억제`) `null`. 정수면 정수, 아니면 소수. 단위나 괄호 표시(`(o)`, `SL`, `SPL`)는 `text` 에만 있으니 장애 판정 등에 쓸 때는 `text` 도 보세요. `inhibition` 에도 같은 규칙을 씁니다.
- `plotted`: 결과지 청력도에 그린 이명 표시(빨강 · 파랑 `T`). 없으면 `null`.
  - `frequency_hz` 는 `pitch_hz` 의 `value`, `level_db_hl` 은 그린 높이(dB HL).
  - `from: "HL"`: 이명 크기가 숫자, `dB`, `dB HL` 이면 그 값 그대로.
  - `from: "SL"`: 이명 크기에 `SL` 이 있으면(`10 dB SL`, `10SL`) 그 귀 기도 역치 + 그 값. 그 주파수를 재지 않았으면 위아래 가장 가까운 두 주파수(무반응 빼고)의 역치를 로그 주파수 축에서 나눠 읽습니다(소수 첫째 자리). 위나 아래에 잰 주파수가 없으면 그리지 않습니다.
  - `SPL` 이면 그리지 않습니다(믿을 만한 변환이 없음). 숫자를 못 읽거나, 그래프 밖(100~10000 Hz, −10~120 dB HL)이어도 그리지 않습니다. 이런 값도 표에는 인쇄됩니다.
