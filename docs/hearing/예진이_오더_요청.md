# 예진이 서버에 부탁: 오늘 검사 오더에 청력검사 코드도 (TSM300 v0.11.0)

2026-11-27. TSM300 쪽에서 예진이 세션에 전하는 글입니다. 약속(`/tsm/api/orders`)은 아직 바꾸지 않았습니다.

## 지금

- TSM300 은 `GET /tsm/api/orders?day=YYYY-MM-DD` (머리글 `X-TSM-Token`)로 오늘 오더를 받습니다.
- 어느 코드를 볼지는 서버가 정합니다. 지금은 임피던스 F6361 · F6362 · F6363 뿐입니다.
- TSM300 v0.11.0 부터 MRS Resonance 청력검사기의 순음 · 어음 · 음장 결과도 받습니다. [설정] → 청력검사기를 켠 PC 는 오더 목록에 청력검사 오더도 보여 주고 싶습니다.
- 매직차트 DB(ODBC)로 직접 읽는 PC 는 이미 됩니다. 예진이 서버를 거치는 PC 만 서버가 바뀌어야 합니다.

## 부탁 (제안)

`/tsm/api/orders` 에 선택 매개변수 `codes` 를 더해 주세요.

```
GET /tsm/api/orders?day=2026-11-27&codes=F6361,F6362,F6363,F6341,F6340,F6300,F0341,F0342,F0343,F0344,F6346
```

- `codes` 가 없으면 지금과 똑같이 F6361~F6363 만. → 지금 병원에 깔린 TSM300(v0.10 이하)은 그대로 동작합니다.
- `codes` 가 있으면 그 코드의 오더가 난 진료. 서버는 위 열한 개 코드 밖의 것은 무시해 주세요(허용 목록).
- 답 모양은 지금과 같습니다. 진료마다 `codes` 목록에 실제로 난 코드가 들어 있으면 TSM300 이 임피던스 · 청력을 나눠 표시합니다.
- 코드는 앞뒤 공백을 빼고 정확히 같은 것만 (`F63411` 같은 긴 코드가 `F6341` 로 잡히지 않게). TSM300 의 ODBC 쪽도 그렇게 합니다.

서버를 기본 목록 자체에 청력 코드를 넣는 식으로 바꾸면, 옛 TSM300 이 청력검사만 있는 오더도 임피던스 목록에 보여 줍니다(코드가 F6341 처럼 그대로 보임). 그래서 `codes` 매개변수를 부탁드립니다.
