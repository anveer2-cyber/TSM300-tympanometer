# 청력검사기(MRS Resonance) 통신 요약

이 프로그램이 청력검사기와 주고받는 것만 적은 요약입니다. 장비와 함께 쓰려고 원프로그램(MDS 3.03)을 살펴본 자세한 기록은 이 저장소에 넣지 않고 따로 둡니다.
해독 규칙은 `src/tsm300/hearing/protocol.py` 에, 받은 결과를 저장하는 JSON 형식은 [원자료_형식.md](원자료_형식.md) 에 있습니다.

## 1. 한눈에

- 연결은 USB(WinUSB)입니다. 드라이버는 MDS 를 설치할 때 깔린 것을 그대로 씁니다(장치 관리자 "Resonance devices → Resonance medical device").
- MDS 가 켜져 있으면 MDS 가 USB 를 잡고 있어 이 프로그램이 장비를 열지 못합니다.
- 받기 순서: 식별 `KC 0x16` → 다시 식별 → 전부 받기 `KC 0x01` → 장비가 환자(`KA`)와 검사(`KT`)를 줄줄이 보냄 → 끝에 `KC Ack(0x06)` → 닫기 `KC 0x07`.
- 검사 패킷(`KT`)에는 환자도 날짜도 없습니다. 그래서 받은 뒤 이 프로그램 화면에서 환자를 고르고, 날짜는 받은 시각으로 적습니다.
- 이 프로그램은 읽는 명령만 보냅니다(§6).

## 2. 연결 (USB)

| 항목 | 내용 |
| --- | --- |
| 장치 | WinUSB 장치. 드라이버 INF 기준 VID 045E · PID 00CE |
| 찾기 | 드라이버가 등록한 장치 인터페이스로 찾음 (`winusb.py`) |
| 읽기 · 쓰기 | 0번 인터페이스의 첫 IN 파이프로 읽고 첫 OUT 파이프로 씀. 명령 하나는 한 번에 씀 |
| 장비가 안 보일 때 | 장비에서 Connect to PC 를 누른 뒤에야 USB 에 나타날 수 있어 30초 동안 1초마다 다시 찾음 (§5.2) |

## 3. 패킷 틀

### 3.1 가변 길이 패킷 (장비 ↔ PC 공통)

| 위치 | 길이 | 내용 |
| --- | --- | --- |
| [0] | 1 | `0x4B` ('K') |
| [1] | 1 | 종류 (§4.1) |
| [2..3] | 2 | n = 자료 길이, 빅엔디언 |
| [4..n+3] | n | 자료 |
| [n+4] | 1 | XOR = 자료 n바이트를 차례로 XOR |
| [n+5] | 1 | `0x6B` ('k') 끝 표시 |

- 전체 길이는 n+6 입니다. 두 종류만 길이가 정해져 있습니다: `K^` 19바이트, `K\` 16바이트.
- 여러 바이트 값은 빅엔디언입니다. 글자는 iso-8859-1, 환자 글자는 UTF-8 입니다.

### 3.2 `KC` 16바이트 명령

| 위치 | 값 |
| --- | --- |
| [0..1] | `4B 43` ('K' 'C') |
| [2..3] | 길이칸. 보통 `00 0A`, USB 식별은 `00 10` |
| [4] | 명령 번호 |
| [5..13] | 인자. 안 쓰면 0 |
| [14] | `[4]..[13]` 10바이트의 XOR |
| [15] | `0x6B` |

이 프로그램이 USB 로 보내는 식별: `4B 43 00 10 16 04 01 00 00 00 00 00 00 00 13 6B` (PC 프로토콜 판 4).

### 3.3 받는 쪽이 견디는 것

USB 로 오는 바이트가 깔끔하지 않아도 좋은 패킷은 모두 살립니다. 시험(`tests/hearing/test_hearing_robustness.py`)으로 확인한 경우:

- 패킷 앞의 잡음, 아주 잘게 또는 크게 쪼개져 오는 바이트
- 길이가 0 인 패킷, 중간에 잘린 패킷, 끝의 짧은 패킷
- XOR 이 틀린 패킷: 값을 쓰지 않고 망가진 조각으로 기록에 남김

원프로그램은 이 가운데 몇 가지에서 받기가 멈춥니다. 이 프로그램은 망가진 조각을 건너뛰고 다음 패킷부터 다시 맞춥니다.

## 4. 장비가 보내는 패킷

### 4.1 종류

| 종류 | 뜻 | 이 프로그램 |
| --- | --- | --- |
| `KI` | 일련번호 (식별의 답) | 장비 번호로 씀 |
| `KC` | Ack(0x06) · Nack(0x07) · Ping(0x05) 등 16바이트 | 식별의 답 · 받기 끝으로 씀 |
| `KA` | 장비에 든 환자 | 검사를 묶는 데 씀 |
| `KT` | 검사 (R2x / R3x 장비) | 해독 |
| `Kt` | 검사 (R1x 장비, 연 · 월 · 일 있음) | 해독 |
| `K^` | 실시간 순음 상태 19바이트 | 받기에서는 안 씀 |
| 그 밖 | 설문 · 첨부 · 장비 정보 등 | 기록에만 남김 |

### 4.2 검사 ↔ 환자 · 날짜

`KT` 머리에는 일련번호 13자, 뜻 모를 1바이트, 모드, 검사 번호만 있습니다. 환자 번호와 날짜는 없습니다.
원프로그램은 바로 앞에 받은 `KA` 환자에 검사를 붙이고, 날짜는 받은 시각으로 적습니다.
이 프로그램은 받은 검사 가운데 이번 환자의 것을 사용자가 고르게 하고(`record.py`), 날짜는 받은 시각으로 적습니다.

장비는 받은 뒤에도 검사를 지우지 않으므로, 받을 때마다 예전 검사도 같이 옵니다. 새 검사인지는 패킷 원본의 지문(SHA-1)으로 가립니다(`Download.new_since`).

## 5. 받기 순서

### 5.1 순서

| 차례 | 방향 | 내용 |
| --- | --- | --- |
| 1 | PC → 장비 | 식별 `KC 0x16` |
| 2 | 장비 → PC | `KI` 일련번호, 또는 `KC Ack` |
| 3 | PC → 장비 | 다시 식별, 그다음 전부 받기 `KC 0x01` |
| 4 | 장비 → PC | 환자마다 `KA` → 그 환자의 검사 `KT` 여러 개 |
| 5 | 장비 → PC | 끝에 `KC Ack`. 6초 동안 아무것도 안 오면 끝으로 봄 |
| 6 | PC → 장비 | 닫기 `KC 0x07` |

### 5.2 장비의 Connect to PC 와 기다리기

병원 장비(R27A)에는 Connect to PC 가 있다고 합니다. 2019년 판 R27A 설명서와 MDS 설명서에는 이 버튼이 없어, 무엇을 하는지는 병원에서 확인해야 합니다. 이 프로그램은 어느 쪽이든 받게 했습니다.

| 경우 | 이 프로그램 |
| --- | --- |
| 버튼을 눌러야 PC 에 답함 (받기 전에 누름) | 그대로 받음 |
| [받기]를 누른 뒤에 버튼을 누름 | 최대 30초 동안 1.5초마다 식별을 다시 보냄. 창에 "장비에서 [Connect to PC]를 눌러 주세요 (남은 시간 n초)" |
| 버튼을 눌러야 USB 에 나타남 | 30초 동안 1초마다 USB 장치를 다시 찾음 |
| 버튼을 누르면 장비가 검사를 스스로 보냄 | 오는 대로 받고 전부 받기는 보내지 않음. 조용해지면 끝 |
| 끝내 답이 없음 | 30초 뒤 "장비에서 [Connect to PC]를 누른 뒤 다시 받아 주세요" |

### 5.3 검사마다 0x07

원프로그램은 USB 에서 다음 두 경우에 검사 하나가 올 때마다 `KC 0x07` 을 돌려줍니다(USB 에서는 "받았음"을 0x07 로 보냄).

- 그 검사 앞에 장비 환자(`KA`)가 하나도 없을 때
- 장비가 묻기 전에 보낸 검사

R27A 는 환자 보관함이 없어 `KA` 없이 검사만 보낼 가능성이 큽니다. 장비가 이 답을 기다린다면, 답이 없을 때 첫 검사 하나만 오고 멈춥니다. 그래서 이 프로그램도 같은 규칙으로 0x07 을 보냅니다(`protocol.USB_TEST_ACK`). `KA` 아래의 검사에는 원프로그램처럼 보내지 않습니다.

### 5.4 연결 시험

[연결 시험]과 `hearing-check` 의 시험은 끝낼 때 0x07 을 보내지 않고 닫습니다. 이 닫기 인사가 "받았음"과 같은 바이트라, 장비가 검사를 다 넘긴 것으로 여길 수 있기 때문입니다.
같은 검사가 한 번 받기에 두 번 오면(스스로 보낸 것 + 전부 받기) 하나만 둡니다.

## 6. 보내지 않는 명령

이 프로그램은 `KC 0x16`(식별), `0x01`(전부 받기), `0x04`(장비 정보), `0x05`(Ping), `0x06` · `0x07`(받았음 · 닫기)만 만들 수 있습니다. `protocol.command()` 가 그 밖의 번호를 거절합니다.

| 보내지 않는 것 | 까닭 |
| --- | --- |
| `KC 0x03` | 장비의 검사를 모두 지움 |
| `KC 0x21` | 일련번호를 씀 |
| `KC 0x22~0x29`, `0x30~0x32` | 보정 값을 바꾸거나 저장함 |
| `KC 0x5D`, `0x5F`, `0x41` | PC 가 소리를 냄. 환자 귀에 큰 소리가 날 수 있음 |
| `KC 0x5B` | PTA 계산 설정을 바꿈 |
| `KC 0x02` + `KA`, `KS`, `KJ`, `KF` | 장비의 환자 목록이나 화면을 바꿈 |
| `K^`, `K\` | 장비 모드를 바꿈 |

## 7. 결과 해독

- 순음: 귀 · 기도/골도/스피커마다 33바이트 묶음, 주파수 13개(125 Hz ~ 12.5 kHz).
- 레벨은 부호 있는 바이트(dB HL)입니다: 246 = −10, 251 = −5. 245 = 값 없음, 244 · 243 = 역치 아래 · 무반응.
- 어음 · 음장 · 고주파도 같은 방식으로 `protocol.py` 가 읽습니다.
- 해독 결과는 원프로그램의 해독 결과와 102개 항목을 대조해 모두 같았습니다. 실제 장비의 패킷으로는 아직 확인 전입니다.

## 8. 실제 장비로 확인할 것

첫 병원 연결 때 `hearing-check` 의 바이트 기록으로 확인합니다.

1. R27A 가 식별에 무엇을 답하나 (`KI` 만, `KC Ack` 도, 순서).
2. R27A 가 검사를 `KT` 로 보내나 `Kt` 로 보내나.
3. 검사 머리의 뜻 모를 1바이트가 환자 번호인지.
4. 전부 받기의 실제 순서, 장비가 받은 표시를 남기거나 검사를 지우는지.
5. 실제 USB 파이프 크기와 종류.
6. Connect to PC 를 누르면 무엇이 바뀌나: USB 에 나타나는지, 식별에 답하기 시작하는지, 검사를 스스로 보내는지 (§5.2).
7. 검사마다 PC 의 0x07 을 기다리나 (§5.3).
8. 음수 역치(−10 dB) 표기, 어음 강도에 +20 이 붙는지.
